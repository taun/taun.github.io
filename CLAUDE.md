# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Eleventy 3 needs Node 18+; `.nvmrc` and CI use Node 22 (the shell default may be older, so `nvm use` first).

```
npm install
npm start        # eleventy --serve at http://localhost:8080
npm run build    # writes _site/ (CI runs npm ci && npm run build, then deploys to GitHub Pages)
```

There are no tests or linter. Verify changes by building and inspecting `_site/`. A failed build writes 0 files, so `--serve` keeps showing the last good page; watch the terminal for the error.

## Architecture

A static site where every page is a **node** (`src/nodes/*.md`), and the views are generated from node front matter. README.md documents the node front matter for authors, and `docs/content-model.md` (with `docs/front-matter.schema.json` and `docs/fixtures/`) is the precise spec used by external tools such as the editor app in `../Breezy`; keep it in sync when changing front matter handling and run `node docs/fixtures/check.mjs`. This section covers how it fits together.

- **`lib/graph.js` `buildGraph()`** turns the node templates into plain records (title, type, ISO date, tags, media, directed `out` links, derived `in` links, undirected `links`). `eleventy.config.js` registers the result as the `graph` collection and exposes it to templates through filters (`nodeInfo`, `relations`, `neighbors`, `sharedTags`, `types`, `byYear`, `byFiveYears`, `talkGroups`, `typeHue`, `typeGlyph`). The collection glob is `src/nodes/*.md` (not recursive), so nodes must stay in one flat folder.
- **Views** all read `collections.graph`: home/blog list (`src/index.md` + `src/_includes/home.njk`), `/cv/` (grouped by year, newest first), `/talks/` (talk nodes grouped by the organization node they link to), `/connections/` (SVG graph, `src/js/graph.js`), and node pages (`src/_includes/node.njk`). The graph page embeds the whole collection as JSON (`graph-embed.njk`).
- **Node pages**: `src/nodes/nodes.11tydata.js` sets the layout and the permalink `/n/<filename-slug>/`. The slug is the filename without `.md` and is the identifier used in `links:`. Duplicate filenames would collide.
- **Links** are directed (declaring node to target). Entries are a slug or `{ to, rel }`; `lib/relations.js` holds the default relation (`led-to`), display wording, and parsing. Unknown targets print a build warning and are dropped.
- **Types** are open-ended: any `type:` value works. The filter chips on the list, the graph checkboxes, and `/css/types.css` (generated by `src/types-css.njk`) are all derived from the types present in the data. Colors come from evenly spaced hues over the sorted types with alternating lightness (`typeHue`, vars in `site.css`); glyphs are inferred from the type name in `lib/glyphs.js`. No per-type CSS or config is needed. Classes use `type-<typeKey>` (`lib/glyphs.js`), a CSS-safe key, never the raw type string.
- **Dates**: a year alone (`date: 2021` or `"2021"`) is converted by the custom front matter parser in `eleventy.config.js` to `2021-01-01` with `datePrecision: year`. Without this Eleventy rejects numeric dates. Undated nodes sort last; in the graph they float toward the dated nodes they connect to. The graph orders nodes left to right by date rank (not proportional time) with a "by date" toggle.
- **Media**: optional `video:`, `archive:`, `slides:`, `repo:` front matter. `lib/media.js` classifies video URLs (YouTube becomes a click-to-load `youtube-nocookie` embed via `src/js/video.js`, `.mp4`/`.webm` becomes a `<video>`, anything else is a link). External links get an arrow icon and open in a new tab.
- **Client scripts** in `src/js/` are dependency-free and copied as-is. `graph.js` is a small force simulation drawn as SVG. `list.js` filters the list by text and type chips.
- Regular pages (About, Contact, 404) are in `src/pages/`; the footer links come from `src/_data/site.json`.
- `markdownTemplateEngine` is `false`, so `{{ }}` and `{% %}` in Markdown stay literal; Nunjucks is only used in `.njk` files.

## Conventions

- Static assets live in `src/assets/` (images, slide PDFs, sounds) and are referenced as `/assets/...`. Page URLs are `/` (home, the blog list), `/talks/`, `/cv/`, `/connections/`, and `/n/<slug>/`.
- Content edits (nodes, `site.json`) are commonly committed separately from code changes, with code first.
