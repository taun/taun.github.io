# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Eleventy 3 needs Node 18+; `.nvmrc` and CI use Node 22 (the shell default may be older, so `nvm use` first).

```
npm install
npm start        # eleventy --serve at http://localhost:8080
npm run build    # writes _site/ (CI runs npm ci && npm run build, then deploys to GitHub Pages)
```

There are no tests or linter. Verify changes by building and inspecting `_site/`. A failed build writes 0 files, so `--serve` keeps showing the last good page; watch the terminal for the error.

## Architecture

A static site where every page is a **node** (`src/nodes/*.md`), and the views are generated from node front matter. README.md documents the node front matter for authors, and `docs/content-model.md` (with `docs/front-matter.schema.json` and `docs/fixtures/`) is the precise spec used by external tools such as the editor app in `../Breezy`; keep it in sync when changing front matter handling and run `node docs/fixtures/check.mjs`. This section covers how it fits together.

- **`lib/graph.js` `buildGraph()`** turns the node templates into plain records (title, type, ISO date, tags, media, directed `out` links, derived `in` links, undirected `links`). `eleventy.config.js` registers the result as the `graph` collection and exposes it to templates through filters (`nodeInfo`, `relations`, `neighbors`, `sharedTags`, `types`, `tagList`, `byYear`, `byFiveYears`, `typeHue`, `typeGlyph`). The collection glob is `src/nodes/*.md` (not recursive), so nodes must stay in one flat folder.
- **Views** are all on the home page (`src/index.md` + `src/_includes/home.njk`), chosen by the query: `view=list|timeline|connections`, filters `type`/`tag` (repeatable; OR within, AND across) and `q`, and `hero=0` (README has the table). Every view is built at build time from `collections.graph` (list by `byFiveYears`, timeline by `byYear`, the SVG graph from the JSON embedded by `graph-embed.njk`). `src/js/view.js` reads and writes the query, sets `<html data-view>` (CSS shows that view) and `no-hero`, hides non-matching `[data-slug]` items and empty `.group`s, and sends the matching slugs to `graph.js` in a `nodefilter` event; the graph then simulates and draws only those (`shown`, plus their neighbors as `.context` when "neighbors" is checked), with date columns from the shown nodes' dates. An inline script in `base.njk` sets those, and `searching` when there is a `q`, from the query before first paint. The search field is in the header on every page (`base.njk`, `src/js/search.js`): `<html class="searching">` shows it over the menu links and hides the home controls; on the home page view.js cancels its submit and filters live, elsewhere it submits to `/?q=…&hero=0`. Without JavaScript the list shows and the controls are hidden. The header menu is `site.menu` (label + query); `src/pages/redirects.njk` makes `/cv/`, `/talks/`, `/connections/` forward to their queries. Node pages are `src/_includes/node.njk`; their type chip and tags link to the filtered home view.
- **Node pages**: `src/nodes/nodes.11tydata.js` sets the layout and the permalink `/n/<filename-slug>/`. The slug is the filename without `.md` and is the identifier used in `links:`. Duplicate filenames would collide.
- **Links** are directed (declaring node to target). Entries are a slug or `{ to, rel }`; `lib/relations.js` holds the default relation (`led-to`), display wording, and parsing. Unknown targets print a build warning and are dropped.
- **Types** are open-ended: any `type:` value works. The filter chips on the list, the graph checkboxes, and `/css/types.css` (generated by `src/types-css.njk`) are all derived from the types present in the data. Colors come from evenly spaced hues over the sorted types with alternating lightness (`typeHue`, vars in `site.css`); glyphs are inferred from the type name in `lib/glyphs.js`. No per-type CSS or config is needed. Classes use `type-<typeKey>` (`lib/glyphs.js`), a CSS-safe key, never the raw type string.
- **Dates**: a year alone (`date: 2021` or `"2021"`) is converted by the custom front matter parser in `eleventy.config.js` to `2021-01-01` with `datePrecision: year`. Without this Eleventy rejects numeric dates. Undated nodes sort last; in the graph they float toward the dated nodes they connect to. The graph orders nodes left to right by date rank (not proportional time) with a "by date" toggle.
- **Media**: optional `video:`, `archive:`, `slides:`, `repo:` front matter. `lib/media.js` classifies video URLs (YouTube becomes a click-to-load `youtube-nocookie` embed via `src/js/video.js`, `.mp4`/`.webm` becomes a `<video>`, anything else is a link). External links get an arrow icon and open in a new tab.
- **Client scripts** in `src/js/` are dependency-free and copied as-is. CSS and script URLs in `base.njk` carry `?v={{ buildStamp }}` (set per build in `eleventy.config.js`) because GitHub Pages lets browsers cache them for 10 minutes; keep it on any new asset link. `graph.js` is a small force simulation drawn as SVG; it lays out the first time the graph has a size, since the page may open on another view. `view.js` runs the home page views and filters; `search.js` opens and closes the header search on every page. `graph.js` must load before `view.js` so it hears the first `nodefilter` event.
- **`.breezy/nodes/<slug>.json`** is Breezy's per-node editor state and drafts (see `docs/content-model.md`): outside `src`, never built, and ignored by the deploy workflow.
- Regular pages (404 and the old-URL forwards) are in `src/pages/`; the footer links, menu and `hero` style come from `src/_data/site.json`.
- `markdownTemplateEngine` is `false`, so `{{ }}` and `{% %}` in Markdown stay literal; Nunjucks is only used in `.njk` files.

## Conventions

- Static assets live in `src/assets/` (images, slide PDFs, sounds) and are referenced as `/assets/...`. Page URLs are `/` (home, every view via its query) and `/n/<slug>/`; `/talks/`, `/cv/`, `/connections/` only forward.
- Content edits (nodes, `site.json`) are commonly committed separately from code changes, with code first.
